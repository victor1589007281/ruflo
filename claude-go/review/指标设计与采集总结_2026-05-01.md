# 指标设计与采集总结

> 文档日期：2026-05-01
> 对应代码：`pkg/metrics/*`、`pkg/engine/metrics.go`、`pkg/agent/modelconfig/metrics.go`、`pkg/observability/metrics_emitter.go`、`pkg/api/client.go`、`config/grafana-dashboard-*.json`

---

## 1. 设计原则

1. **复用现有基础设施**：不重建 Prometheus client，通过 `metrics.Collector` 写入，复用既有的 `prom_registry` 和 HTTP `/metrics` 端点。
2. **标签丰富**：每个指标都带上 `model_alias`、`stage`、`role`、`team`、`workflow` 等维度，支持 Grafana 多层级下钻。
3. **分层清晰**：LLM 层关注调用量和延迟，Team 层关注成功率与产出，Prompt 层关注渲染效率与版本差异，Dreaming/Memory/Evolution 层关注各自领域健康度。
4. **错误可观测**：LLM 错误细分为 rate_limit / overloaded / timeout / refusal / prompt_too_long，便于快速定位根因。

---

## 2. 指标采集体系总览

当前代码中存在**多个指标采集系统**，各司其职：

| 系统 | 位置 | 核心职责 | 输出目标 |
|---|---|---|---|
| **Prometheus Registry** | `pkg/metrics/prom_registry.go` | 原生 prometheus/client_golang 注册表 | `/metrics` HTTP 端点 |
| **Collector** | `pkg/metrics/module_metrics.go` | 内存缓冲 + JSONL 持久化 + Prometheus 桥接 | Prometheus + JSONL |
| **LLM Collector** | `pkg/metrics/llm_collector.go` | 全局 LLM 指标采集 | Prometheus + JSONL |
| **AliasMetrics** | `pkg/agent/modelconfig/metrics.go` | 按 alias 聚合 LLM 统计 | JSONL (`alias_llm.jsonl`) |
| **EngineMetrics** | `pkg/engine/metrics.go` | 引擎级 lock-free 原子计数器 | 内存 Snapshot（dashboard 消费） |
| **MetricsEmitter** | `pkg/observability/metrics_emitter.go` | 将 observability hook 事件桥接到 Collector | Prometheus |

## 4. 指标常量定义（`pkg/metrics/module_metrics.go`）

所有指标名称以 Go 常量形式集中定义，避免拼写错误：

```go
const (
    MLLMCallCount      = "llm_call_count"
    MLLMSuccessCount   = "llm_success_count"
    MLLMErrorCount     = "llm_error_count"
    MLLMDurationSec    = "llm_duration_sec"
    MLLMInputTokens    = "llm_input_tokens"
    // ... 共 70+ 个常量
)
```

`MetricType` map 定义每个常量的 Prometheus 类型（`counter` / `gauge` / `histogram`），`recordPromMetric` 根据类型调用 `.Add()` / `.Set()` / `.Observe()`。

## 5. 采集链路

### 5.1 LLM 指标采集链路

```
api.Client 发起调用
   │
   ▼
emitLLMMetric(rec)
   ├──► c.OnLLMMetrics(rec)        [client 实例级 hook]
   └──► globalLLMHook(rec)         [全局 hook]
           │
           ▼
    metrics.InitGlobalLLMCollector
           │
           ▼
    recordLLMCall(c, rec)
           │
           ├──► c.RecordAtTime(...) ──► recordPromMetric(...) ──► Prometheus
           └──► c.appendJSONL(...) ──► {stateDir}/metrics/llm.jsonl
```

**`pkg/feishu/bot.go` 的链式 hook**：

```go
oldHook := aiClient.OnLLMMetrics
aiClient.OnLLMMetrics = func(rec api.LLMCallRecord) {
    if oldHook != nil { oldHook(rec) }     // 保留全局 collector
    aliasMetrics.Record(rec)               // alias 级聚合
    observability.Emit(...)                // observability Bus
}
```

### 5.2 Team/Stage 指标采集链路

```
workflow.Execute / executeStage
   │
   ▼
observability.Emit(Event)
   │
   ▼
BusSubscriber.OnEvent
   │
   ▼
MetricsEmitter.OnStageComplete / OnTeamComplete
   │
   ▼
metrics.Collector.RecordWithLabels
   │
   ├──► recordPromMetric(...) ──► Prometheus
   └──► appendJSONL(...) ──► {stateDir}/metrics/team.jsonl
```

### 5.3 其他模块指标

各模块直接调用 `metrics.Collector.RecordWithLabels` 或 `Record`：
- `pkg/engine/metrics.go` — `EngineMetrics` 提供 lock-free 原子计数器，供 dashboard 通过 `Snapshot()` 读取，**不走 Prometheus**。
- `pkg/dreaming/`、`pkg/memory/`、`pkg/agent/evolution.go` 等 — 直接调用 `metrics.Collector`。

## 6. EngineMetrics — 引擎级原子指标

**文件**：`pkg/engine/metrics.go`

独立于 Prometheus 体系，使用 `atomic.Int64` + `sync.Map` 实现 lock-free：

| 字段 | 含义 |
|---|---|
| `TurnsTotal/Success/Aborted/Error` | 轮次统计 |
| `ToolCallsTotal/LoopsDetected/LoopsSuppressed` | 工具调用与循环检测 |
| `JSONRepairsApplied/Failed` | JSON 修复 |
| `CacheHits/Misses` | Prompt Cache |
| `budgetDegradations` | 预算分级降级（sync.Map） |
| `errorsByFamily` | 错误族统计（sync.Map） |
| `StopSuggestionsEmitted/Honored` | 停止建议 |
| `TotalTurnLatencyMs` | 累计延迟 |
| `TrajSuccessRecorded/FailRecorded` | 轨迹记录 |

通过 `Snapshot()` 导出为 `map[string]any`，供 dashboard 直接消费。

## 7. AliasMetrics — 按模型别名聚合

**文件**：`pkg/agent/modelconfig/metrics.go`

独立于 Prometheus，按 alias 维度聚合 LLM 调用：

```go
type AliasMetrics struct {
    Alias, Provider, ProviderName string
    Calls, Errors, RateLimitErrors, TimeoutErrors, OverloadedErrors, OtherErrors int64
    InputTokens, OutputTokens, CacheReadTokens, CacheCreateTokens, TotalTokens int64
    TotalDurationSec, GuardWaitSec float64
}
```

- 通过 `resolveAlias(rawModel)` 将原始 model 名反查为 `provider:modelName` alias。
- 同时维护 `_total` 汇总维度。
- 持久化到 `{stateDir}/metrics/alias_llm.jsonl`。

## 8. JSONL 回放机制

**文件**：`pkg/metrics/prom_registry.go:825-915`

服务重启时，从 `{stateDir}/metrics/*.jsonl` 回放最近 N 条（默认 10000）事件到 Prometheus，使 counter/histogram 保留历史累计值。

```go
func RestorePromFromJSONL(stateDir string, maxEvents int) error
```

在 `InitGlobalLLMCollector` 中异步启动：

```go
go func() { _ = RestorePromFromJSONL(stateDir, 20000) }()
```

## 10. 扩展方式

新增一个指标：

1. 在 `pkg/metrics/module_metrics.go` 添加新常量（如 `MNewMetric = "new_metric"`）。
2. 在 `MetricType` map 中声明类型（`counter` / `gauge` / `histogram`）。
3. 在 `pkg/metrics/prom_registry.go` 的 `initPrometheusMetrics` 中创建对应的 `prometheus.Collector`。
4. 在 `recordPromMetric` 的 switch 中添加路由分支。
5. 在业务代码中调用 `collector.RecordWithLabels("module", MNewMetric, value, labels)`。
6. 在 Grafana dashboard JSON 中添加对应面板。

无需修改 Hook 体系或 EventBus。
