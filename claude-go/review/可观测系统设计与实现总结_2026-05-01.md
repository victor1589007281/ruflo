# 可观测系统设计与实现总结

> 文档日期：2026-05-01
> 对应代码：`pkg/observability/*`

---

## 1. 设计目标

基于当前代码，可观测系统的核心诉求是**全链路追踪、多维度持久化、非侵入式接入**：

1. **Trace 贯穿**：从 LLM 调用到 Team 完整执行的每一步都有唯一 TraceID 串联。
2. **多维度持久化**：事件既上 Prometheus（通过 metrics.Collector），也落盘 JSONL，还进入 SQLite 做细粒度查询。
3. **零侵入**：业务代码只调用 `observability.Emit(...)`，不感知下游存储细节。
4. **自动轮转**：JSONL 按日轮转，SQLite 在驱动缺失时优雅降级。

## 3. 核心组件

### 3.1 EventBus — 事件总线

**文件**：`pkg/observability/eventbus.go`

```go
type Bus struct {
    mu   sync.RWMutex
    subs []Subscriber
}

type Event struct {
    Type      EventType
    Timestamp time.Time
    TraceID   string
    SpanID    string
    ParentID  string
    Module    string
    Name      string
    Payload   map[string]interface{}
}
```

关键特性：
- **非阻塞发布**：`Emit` 遍历 subscriber 列表同步调用，每个 subscriber 预期自身实现轻量或异步缓冲。
- **panic 恢复**：每个 subscriber 调用被 `defer recover()` 包裹，单个 subscriber 崩溃不影响其他 subscriber。
- **全局默认实例**：`GlobalBus()` 提供进程级默认总线，业务代码直接 `observability.Emit(...)` 即可。
- **25 种事件类型**：覆盖 LLM、Stage、Task、Team、Collaboration、Prompt、Trace 七大域。

### 3.2 TraceContext — 调用链追踪

**文件**：`pkg/observability/trace.go`

兼容 OpenTelemetry 语义，支持 TraceID → SpanID → ParentID 三级嵌套：

```go
type TraceContext struct {
    TraceID  string
    SpanID   string
    ParentID string
    Baggage  map[string]string
}
```

关键 API：

| 函数 | 作用 |
|------|------|
| `NewRootTrace()` | 创建根 trace |
| `tc.NewChild()` | 从当前 trace 创建子 span |
| `WithTrace(ctx, tc)` | 将 trace 注入 context |
| `TraceFromContext(ctx)` | 从 context 提取 trace |
| `EnsureTrace(ctx)` | 若 context 无 trace，自动新建 |
| `StartSpan(ctx, module, name)` | 创建 span 并自动发射 `EvtTraceSpan` start/end 事件 |

`Span.Finish()` 会在结束时发射 `EvtTraceSpan`（含 `duration`）。

**ActiveSpanStore** 提供内存中的活跃 span 查询，供 dashboard 实时展示当前进行中的调用。

### 3.3 JSONLStore — 结构化事件落盘

**文件**：`pkg/observability/jsonl_store.go`

- **按事件类型分文件**：`llm_call_complete.jsonl`、`stage_complete.jsonl` 等。
- **追加写**：每条事件一行 JSON，方便 `tail -f` 和外部日志采集器读取。
- **并发安全**：`sync.Mutex` 保护文件句柄映射。
- **文件名安全**：`sanitizeFilename` 过滤危险字符，保留字母数字和 `_-:.`。

辅助能力：

| 能力 | 说明 |
|------|------|
| `RotateDaily()` | 关闭当前文件句柄，新事件自动创建新文件 |
| `DailyRotator` | 后台 goroutine，在 00:00 自动触发轮转 |
| `TraceQuery(dir, traceID)` | 扫描所有 JSONL 文件，按 TraceID 聚合事件，用于故障排查 |
| `EventFilterSubscriber` | 只订阅指定事件类型，减少无效写入 |

### 3.4 PromptObservatory — 提示词版本与 A/B 测试

**文件**：`pkg/observability/prompt_observatory.go`

基于 SQLite，Schema 包含 4 张表：

| 表 | 用途 |
|---|---|
| `prompt_versions` | 每次提示词渲染记录（prompt_id, version, hash, template, rendered, render_time_ms） |
| `prompt_outcomes` | 使用结果（success, tokens_in/out, latency_ms），用于计算 success_rate |
| `prompt_ab_tests` | A/B 测试元数据（variant_a/b, config, start/end, status） |
| `prompt_ab_outcomes` | A/B 测试单次结果（variant, success, tokens, latency） |

核心 API：

```go
RecordPrompt(rec PromptRecord) (int64, error)
LookupVersion(promptID, version string) (*PromptRecord, error)
VersionStats(promptID string) ([]PromptVersionStats, error)
RecordOutcome(promptID, version string, success bool, tokensIn, tokensOut int, latencyMs float64) error
StartABTest(testID, promptID, variantA, variantB string, config map[string]string) error
ABResult(testID string) (*PromptABResult, error)
HashPrompt(prompt string) string // SHA256 前 16 位，作为版本指纹
```

**PromptHookAdapter** 将 `PromptHook` 事件自动写入 Observatory。当前实现记录 `OnPromptRender`（完整渲染记录）和 `OnPromptVersion`（版本标记），A/B 测试结果由业务层通过 `ABResult` 查询后决策。

### 3.5 System — 全局初始化入口

**文件**：`pkg/observability/global.go`

```go
type System struct {
    Bus         *Bus
    Registry    *HookRegistry
    Emitter     *MetricsEmitter
    JSONLStore  *JSONLStore
    Observatory *PromptObservatory
    ActiveSpans *ActiveSpanStore
    Rotator     *DailyRotator
}
```

`InitSystem(stateDir)` 统一初始化所有组件：

1. 新建 `Bus` 并替换全局实例
2. 新建 `HookRegistry`，注册 `MetricsEmitter` 到全部 6 类 hook
3. 创建 `JSONLStore`（目录 `stateDir/observability`），订阅到 Bus
4. 创建 `PromptObservatory`（`stateDir/prompt_observatory.db`），失败则记录日志并继续
5. 创建 `BusSubscriber` 并订阅到 Bus，负责将 Event 路由到 HookRegistry
6. 创建 `ActiveSpanStore` 和 `DailyRotator`

默认路径：`~/.claude-go/state`。业务代码在 `NewBot` 中调用：

```go
observability.InitSystem(layout.Root)
```

## 4. 接入点（Wiring）

### 4.1 LLM 调用层

**文件**：`pkg/feishu/bot.go:374-399`

在 `aiClient.OnLLMMetrics` hook 中链式调用：
1. `oldHook(rec)` — 保留原有 hook（全局 metrics collector）
2. `aliasMetrics.Record(rec)` — 按 alias 聚合
3. `observability.Emit(Event{Type: EvtLLMCallComplete, ...})` — 发射到可观测 Bus

Trace 信息通过 `EnsureTrace` 在调用链上层注入。

### 4.2 Workflow Stage 层

**文件**：`pkg/agent/workflow.go`

- `Execute()` 在入口调用 `EnsureTrace(ctx)` 注入根 trace，发射 `EvtTeamStart`。
- `executeStage()` 在开头发射 `EvtStageStart`；结束时计算 duration，发射 `EvtStageComplete` 或 `EvtStageFail`。
- defer 中发射 `EvtTeamComplete` 或 `EvtTeamFail`。

### 4.3 Orchestrator DAG 层

**文件**：`pkg/orchestrator/orchestrator_bridge.go`

`ObservabilityBridge` 实现 `orchestrator.LifecycleHook`，将引擎生命周期事件转换为 observability `Event`（详见 Hook 体系文档）。

## 5. 持久化策略对比

| 维度 | Prometheus (metrics.Collector) | JSONL | SQLite (PromptObservatory) |
|---|---|---|---|
| 查询方式 | PromQL / Grafana | `grep` / `jq` / `TraceQuery` | SQL |
| 保留周期 | 由 Prometheus TSDB 配置决定 | 文件系统，可压缩归档 | 持久化，需手动清理 |
| 适用场景 | 实时监控、告警 | 事后审计、trace 回放 | 提示词版本对比、A/B 测试 |
| 写入性能 | 内存计数器，极快 | 磁盘追加，快 | 事务插入，中等 |
| 是否阻塞业务 | 否（subscriber 同步但轻量） | 否 | 否（PromptHookAdapter 异步感） |

---

## 6. 扩展方式

新增一种持久化后端只需三步：

1. 实现 `Subscriber` 接口（`OnEvent(e Event)`）。
2. 在 `InitSystem` 中初始化该后端，调用 `bus.Subscribe(mySub)`。
3. 如需按类型过滤，用 `NewEventFilterSubscriber` 包装。

无需修改任何业务代码。
