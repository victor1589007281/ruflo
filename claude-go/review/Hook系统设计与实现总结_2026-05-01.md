# Hook 系统设计与实现总结

> 文档日期：2026-05-01
> 对应代码：`pkg/observability/`、`pkg/orchestrator/hooks.go`、`pkg/orchestrator/orchestrator_bridge.go`

---

## 1. 设计目标

Hook 系统的核心诉求是**非侵入式可观测**：业务代码无需修改函数签名，只需在关键生命周期节点发射事件，所有观测逻辑（metrics、日志、持久化、告警）通过外部订阅者异步消费。

三大设计原则：

| 原则 | 说明 |
|------|------|
| 非侵入 | 业务代码只依赖 `observability.Emit`，不依赖 metrics/prometheus 细节 |
| 可扩展 | 新增观测维度只需注册新 subscriber，无需改动现有代码 |
| 零耦合 | 发射端与消费端完全解耦，subscriber panic 不影响主流程 |

## 3. 核心组件

### 3.1 EventBus — 事件总线

**文件**：`pkg/observability/eventbus.go`

```go
type Bus struct {
    mu    sync.RWMutex
    subs  []Subscriber
}

type Event struct {
    Type      EventType              // 枚举: llm:call:complete / stage:start / task:complete ...
    Timestamp time.Time
    TraceID   string                 // 贯穿调用链
    SpanID    string
    Module    string                 // 模块名: llm / workflow / orchestrator
    Name      string
    Payload   map[string]interface{} // 结构化负载
}
```

关键特性：

- **非阻塞发布**：`Emit` 遍历 subscriber 列表同步调用，但每个 subscriber 预期自身实现轻量或异步缓冲
- **panic 恢复**：每个 subscriber 调用都被 `defer recover()` 包裹，单个 subscriber 崩溃不影响其他 subscriber
- **全局默认实例**：`GlobalBus()` 提供进程级默认总线，业务代码直接 `observability.Emit(...)` 即可

### 3.2 六大 Hook 接口

**文件**：`pkg/observability/hooks.go`

| Hook 接口 | 观测对象 | 关键方法 |
|-----------|----------|----------|
| `LLMHook` | 大模型调用 | `OnLLMCallStart/Complete/Error/Fallback`, `OnLLMCacheHit/Miss` |
| `StageHook` | 工作流 Stage | `OnStageStart/Complete/Fail/Retry` |
| `TaskHook` | Orchestrator DAG 任务 | `OnTaskReady/Start/Complete/Fail/Retry` |
| `TeamHook` | 整团队运行 | `OnTeamStart/Complete/Fail`, `OnTeamStageTransition` |
| `CollaborationHook` | Agent 协作交互 | `OnCollabMessage/Review/Consensus/Handoff` |
| `PromptHook` | 提示词版本与 A/B | `OnPromptRender/Version/Compare/ABStart/ABResult` |

每个接口都有对应的 `NoopXxxHook` 空实现，方便选择性覆盖。

### 3.3 HookRegistry — 注册表

统一管理所有 hook 实例，作为 `BusSubscriber` 的分发入口：

```go
type HookRegistry struct {
    LLM           []LLMHook
    Stage         []StageHook
    Task          []TaskHook
    Team          []TeamHook
    Collaboration []CollaborationHook
    Prompt        []PromptHook
}
```

### 3.4 BusSubscriber — 事件路由适配器

**文件**：`pkg/observability/metrics_emitter.go:375+`

将 `Event` 按 `Type` 路由到对应 hook 接口。核心逻辑：

```go
func (s *BusSubscriber) OnEvent(e Event) {
    switch e.Type {
    case EvtLLMCallComplete:
        ev := s.toLLMEvent(e)
        for _, h := range s.registry.LLM {
            safeCall(func() { h.OnLLMCallComplete(ev) })
        }
    case EvtStageStart:
        ev := s.toStageEvent(e)
        for _, h := range s.registry.Stage {
            safeCall(func() { h.OnStageStart(ev) })
        }
    // ... 其他类型
    }
}
```

`safeCall` 再次包裹 panic 恢复，确保 subscriber 内部崩溃不会传播。

## 4. 接入点（Wiring）

### 4.1 LLM 调用层

**文件**：`pkg/feishu/bot.go`

在 `aiClient.OnLLMMetrics` hook 中，除原有的 alias metrics 外，新增 observability 事件发射：

```go
aiClient.OnLLMMetrics = func(rec api.LLMCallRecord) {
    if oldHook != nil { oldHook(rec) }
    aliasMetrics.Record(rec)
    observability.Emit(Event{
        Type:      observability.EvtLLMCallComplete,
        Timestamp: rec.Timestamp,
        Payload: map[string]interface{}{
            "record":       rec,
            "model":        rec.Model,
            "status":       rec.Status,
            "duration_sec": rec.DurationSec,
            ...
        },
    })
}
```

### 4.2 Workflow Stage 层

**文件**：`pkg/agent/workflow.go`

`executeStage` 在开头和结尾分别发射 `EvtStageStart` 和 `EvtStageComplete/EvtStageFail`：

```go
func (we *WorkflowExecutor) executeStage(...) StageResult {
    // stage start
    observability.Emit(Event{Type: EvtStageStart, ...})
    
    sr := we.executeStageWithRetry(...)
    
    // stage end
    if sr.Status == TaskCompleted {
        observability.Emit(Event{Type: EvtStageComplete, ...})
    } else {
        observability.Emit(Event{Type: EvtStageFail, ...})
    }
    return sr
}
```

`Execute` 方法在入口注入根 trace，并在 `defer` 中发射 `EvtTeamStart/EvtTeamComplete/EvtTeamFail`。

### 4.3 Orchestrator DAG 层

**文件**：`pkg/agent/workflow_orchestrated.go`、`pkg/orchestrator/orchestrator_bridge.go`

将 `pkg/orchestrator` 已有的 `LifecycleHook` 桥接到 observability Bus：

```go
eng.SetHook(orchestrator.NewMultiHook(
    expanderHook, metricsHook, stageFlusher,
    orchestrator.NewObservabilityBridge(),  // 新增
))
```

`ObservabilityBridge` 实现 `LifecycleHook` 接口，将 `OnTaskStart/Complete/Fail/Retry`、`OnGraphStart/Complete`、`OnStallDetected` 等事件转换为 observability `Event` 并发射。

## 5. 与现有 Hook 体系的关系

claude-go 中存在三套 hook/回调机制，本设计实现了**统一收编**：

| 原有机制 | 位置 | 本设计中的角色 |
|----------|------|----------------|
| `api.LLMMetricsHook` | `pkg/api/client.go` | **数据源**：`OnLLMMetrics` 回调中发射 observability 事件 |
| `orchestrator.LifecycleHook` | `pkg/orchestrator/hooks.go` | **数据源**：通过 `ObservabilityBridge` 桥接到 Bus |
| `hooks.HookRunner` | `pkg/hooks/hooks.go` | 独立保留，负责权限/生命周期 hook，不参与可观测 |

本设计的 EventBus 位于架构**更底层**，将分散的 hook 数据源统一汇聚到单一事件流，再分发给 metrics、JSONL、Prompt Observatory 等多个消费者。

---

## 6. 扩展方式

新增一个观测维度（如"发送 Slack 告警"）只需三步：

1. 实现 `Subscriber` 接口（或 `SubscriberFunc`）
2. 调用 `observability.Subscribe(mySubscriber)`
3. 在 `OnEvent` 中按 `e.Type` 过滤并处理

无需修改任何业务代码。
