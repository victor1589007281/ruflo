# Hook 体系设计与实现总结

> 文档日期：2026-05-01
> 对应代码：`pkg/hooks/hooks.go`、`pkg/orchestrator/hooks.go`、`pkg/observability/*`

---

## 1. 概述

当前代码库中存在**三套独立的 Hook 体系**，分别服务于不同层级的需求：

| 体系 | 位置 | 核心用途 | 事件粒度 |
|---|---|---|---|
| **HookRunner** | `pkg/hooks/hooks.go` | 工具生命周期干预（权限/阻断/通知） | 工具调用级 |
| **LifecycleHook** | `pkg/orchestrator/hooks.go` | DAG 引擎执行状态观测 | 任务/图级 |
| **Observability Hook** | `pkg/observability/` | 全链路可观测（metrics/日志/持久化） | LLM/Stage/Task/Team/Prompt |

三套体系互不依赖，通过桥接层实现事件转发。

---

## 2. HookRunner — 工具生命周期干预

**文件**：`pkg/hooks/hooks.go`

这是最早的 hook 系统，移植自 TS 源码，用于在工具执行前后运行用户自定义逻辑。

### 2.1 架构

```
配置 (types.HookConfig[]) → Runner → 按 Event+If 匹配 → 执行 (shell/http/prompt)
```

### 2.2 支持的事件类型

| 事件 | 触发时机 | 能力 |
|---|---|---|
| `PreToolUse` | 工具执行前 | 可阻断（`decision="block"`），可注入 AdditionalContext |
| `PostToolUse` | 工具执行后 | 观测，不可阻断 |
| `PostToolUseFailure` | 工具执行失败后 | 观测 |
| `Stop` | 模型回复完成且无 tool_use | 可注入阻止消息让模型继续处理 |
| `StopFailure` | 模型回复失败 | 同上 |
| `SessionStart/End` | 会话开始/结束 | 生命周期通知 |
| `PreCompact/PostCompact` | 上下文压缩前后 | 观测 |
| `SubagentStart/Stop` | 子代理启停 | 观测 |
| `TeammateIdle` | Agent Teams 队友空闲 | 自动分配任务 |
| `TaskCompleted` | Agent Teams 任务完成 | 训练模式 |

### 2.3 执行方式

| 类型 | 说明 |
|---|---|
| `command` | `sh -c "..."`，stdin 传入 JSON，stdout 解析 HookOutput |
| `prompt` | 不执行命令，将 Command 字段作为 AdditionalContext 返回 |
| `http` | POST JSON 到 URL，解析响应 JSON |

### 2.4 阻断机制

- Shell 退出码 2 → 触发 `block`，stderr 作为原因。
- HTTP 返回的 JSON 中 `Decision="block"` → 触发阻断。
- 单个 hook panic → 捕获并继续后续 hook。

### 2.5 与可观测系统的关系

**不参与**。HookRunner 专注于权限和交互干预，不输出 metrics，也不接入 EventBus。

## 3. LifecycleHook — Orchestrator DAG 引擎事件

**文件**：`pkg/orchestrator/hooks.go`

服务于 `pkg/orchestrator` 的 DAG 执行引擎，暴露图级别和任务级别的生命周期。

### 3.1 接口定义

```go
type LifecycleHook interface {
    OnGraphStart(g *Graph)
    OnTaskReady(t *Task)        // 依赖满足，可调度
    OnTaskStart(t *Task)
    OnTaskComplete(t *Task, output any)
    OnTaskFailed(t *Task, err error)
    OnTaskRetry(t *Task, attempt int, delay interface{})
    OnTaskSuspended(t *Task, err error)
    OnGraphComplete(g *Graph, metrics ExecutionMetrics)
    OnStallDetected(g *Graph, stuckTasks []*Task)
    OnCheckpoint(execID string, state *ExecutionState)
}
```

### 3.2 MultiHook 扇出

```go
eng.SetHook(orchestrator.NewMultiHook(
    expanderHook, metricsHook, activityHook, stageFlusher, obsBridge,
))
```

引擎只持有单个 `LifecycleHook`，`MultiHook` 将事件同步扇出到多个实现。

### 3.3 现有实现

| 实现 | 位置 | 作用 |
|---|---|---|
| `expanderHook` | `pkg/orchestrator/engine.go` | 任务展开 |
| `metricsHook` | `pkg/orchestrator/engine.go` | 引擎内部指标采集 |
| `activityHook` | `pkg/orchestrator/engine.go` | 活跃状态通知 |
| `stageFlusher` | `pkg/orchestrator/engine.go` | Stage 结果刷盘 |
| `ObservabilityBridge` | `pkg/orchestrator/orchestrator_bridge.go` | 桥接到 observability EventBus |

### 3.4 ObservabilityBridge

```go
type ObservabilityBridge struct{}
```

实现 `LifecycleHook`，将引擎事件转换为 `observability.Event` 发射到全局 Bus：

| 引擎事件 | 对应 Event | Payload |
|---|---|---|
| `OnGraphStart` | `EvtTeamStart` | graph_id, graph_name, node_count |
| `OnTaskReady` | `EvtTaskReady` | task_id, task_name, dependencies |
| `OnTaskStart` | `EvtTaskStart` | task_id, task_name, attempt |
| `OnTaskComplete` | `EvtTaskComplete` | task_id, task_name, success |
| `OnTaskFailed` | `EvtTaskFail` | task_id, task_name, error, attempt |
| `OnTaskRetry` | `EvtTaskRetry` | task_id, task_name, attempt, delay_ms |
| `OnGraphComplete` | `EvtTeamComplete` | graph_id, completed, failed, total_duration |
| `OnStallDetected` | `EvtTeamFail` | graph_id, stuck_count, event="stall_detected" |

## 4. Observability Hook — 全链路可观测

**文件**：`pkg/observability/hooks.go`、`eventbus.go`

这是新引入的统一可观测层，通过 **EventBus + 6 类 Hook 接口** 实现非侵入式观测。

### 4.1 EventBus

```go
type Bus struct {
    mu   sync.RWMutex
    subs []Subscriber
}

type Event struct {
    Type      EventType
    Timestamp time.Time
    TraceID   string
    SpanID    string
    ParentID  string
    Module    string
    Name      string
    Payload   map[string]interface{}
}
```

关键行为：
- **全局默认实例**：`GlobalBus()` / `Emit()`
- **panic 恢复**：每个 subscriber 调用被 `defer recover()` 包裹
- **非阻塞**：`Emit` 同步遍历，subscriber 预期自身轻量或异步缓冲

### 4.2 事件类型（25 种）

| 域 | 事件类型 |
|---|---|
| LLM | `llm:call:start` `llm:call:complete` `llm:call:error` `llm:call:fallback` `llm:cache:hit` `llm:cache:miss` |
| Stage | `stage:start` `stage:complete` `stage:fail` `stage:retry` |
| Task | `task:start` `task:complete` `task:fail` `task:retry` `task:ready` |
| Team | `team:start` `team:complete` `team:fail` `team:stage` |
| Collab | `collab:message` `collab:review` `collab:consensus` `collab:handoff` |
| Prompt | `prompt:render` `prompt:version` `prompt:compare` `prompt:ab:start` `prompt:ab:result` |
| Trace | `trace:start` `trace:span` `trace:end` |

### 4.3 六大 Hook 接口

```go
type LLMHook interface {
    OnLLMCallStart(ev LLMCallEvent)
    OnLLMCallComplete(ev LLMCallEvent)
    OnLLMCallError(ev LLMCallEvent)
    OnLLMCallFallback(primary, fallback string, ev LLMCallEvent)
    OnLLMCacheHit(model, cacheType string, tokens int)
    OnLLMCacheMiss(model, cacheType string, tokens int)
}

type StageHook interface {
    OnStageStart(ev StageEvent)
    OnStageComplete(ev StageEvent)
    OnStageFail(ev StageEvent)
    OnStageRetry(ev StageEvent, attempt int, delay time.Duration)
}

type TaskHook interface {
    OnTaskReady(ev TaskEvent)
    OnTaskStart(ev TaskEvent)
    OnTaskComplete(ev TaskEvent)
    OnTaskFail(ev TaskEvent)
    OnTaskRetry(ev TaskEvent, attempt int, delay time.Duration)
}

type TeamHook interface {
    OnTeamStart(ev TeamEvent)
    OnTeamComplete(ev TeamEvent)
    OnTeamFail(ev TeamEvent)
    OnTeamStageTransition(fromStage, toStage string, ev TeamEvent)
}

type CollaborationHook interface {
    OnCollabMessage(ev CollaborationEvent)
    OnCollabReview(ev CollaborationEvent)
    OnCollabConsensus(ev CollaborationEvent)
    OnCollabHandoff(fromRole, toRole string, contextSummary string, ev CollaborationEvent)
}

type PromptHook interface {
    OnPromptRender(ev PromptEvent)
    OnPromptVersion(promptID, version, hash string, metadata map[string]string)
    OnPromptCompare(v1, v2 string, diffStats map[string]int)
    OnPromptABStart(testID, variantA, variantB string, ev PromptEvent)
    OnPromptABResult(res PromptABResult)
}
```

每个接口都有对应的 `NoopXxxHook` 空实现。

### 4.4 HookRegistry

```go
type HookRegistry struct {
    LLM           []LLMHook
    Stage         []StageHook
    Task          []TaskHook
    Team          []TeamHook
    Collaboration []CollaborationHook
    Prompt        []PromptHook
}
```

全局实例：`GlobalRegistry()`。

### 4.5 BusSubscriber — 统一路由适配器

**文件**：`pkg/observability/metrics_emitter.go`

```go
type BusSubscriber struct{ registry *HookRegistry }
```

实现 `Subscriber` 接口，`OnEvent` 中按 `e.Type` 做 type switch：
- 将 `Event` 转换为对应的 `XxxEvent` struct
- 遍历 `HookRegistry` 中对应类型的 hook 列表
- 每个 hook 调用被 `safeCall`（`defer recover()`）包裹

这是 EventBus 与 Hook 接口之间的唯一适配层。

## 5. 接入点（Wiring）

### 5.1 LLM 调用层

**文件**：`pkg/feishu/bot.go:374-399`

```go
oldHook := aiClient.OnLLMMetrics
aiClient.OnLLMMetrics = func(rec api.LLMCallRecord) {
    if oldHook != nil { oldHook(rec) }
    aliasMetrics.Record(rec)
    observability.Emit(Event{
        Type:      EvtLLMCallComplete,
        Module:    "llm",
        Name:      rec.Status,
        Payload: map[string]interface{}{
            "record": rec, "model": rec.Model, "status": rec.Status,
            "source": rec.Source, "purpose": rec.Purpose,
            "duration_sec": rec.DurationSec, ...
        },
    })
}
```

链路：`api.Client.emitLLMMetric` → `aiClient.OnLLMMetrics` → `aliasMetrics.Record` + `observability.Emit`

### 5.2 Workflow Stage 层

**文件**：`pkg/agent/workflow.go`

`Execute()`：
- 注入根 Trace：`observability.NewRootTrace().WithBaggage("team_id", ...)`
- 发射 `EvtTeamStart`
- defer 中发射 `EvtTeamComplete` / `EvtTeamFail`

`executeStage()`：
- 开头发射 `EvtStageStart`
- 结尾发射 `EvtStageComplete` / `EvtStageFail`

### 5.3 Orchestrator DAG 层

**文件**：`pkg/agent/workflow_orchestrated.go:109-111`

```go
eng.SetHook(orchestrator.NewMultiHook(
    expanderHook, metricsHook, activityHook, stageFlusher,
    orchestrator.NewObservabilityBridge(), // 桥接
))
```

## 7. 扩展方式

新增一个观测维度：

1. 实现 6 类 Hook 接口中的任意一个（或实现 `Subscriber` 接口直接消费 Event）。
2. 调用 `observability.GlobalRegistry().RegisterXxx(h)` 或 `observability.Subscribe(s)`。
3. 在 `InitSystem` 中注册到 Bus（若需要）。

无需修改任何业务代码。
