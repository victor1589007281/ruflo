# Agent Note: F12 goal state machine CAS — event sourcing + optimistic concurrency

Status: implemented

English | [中文](2026-09-06-f12-goal-cas.md)

## Problem

Dynamic workflow goal decomposition (design/01 §4.5) already had a goal tree, but multiple agents mutating goals concurrently had **no conflict detection**: internal transitions were last-writer-wins, and any external updater could **silently overwrite** someone else's change via an unversioned read-modify-write. The spec (docforge planning-dsh-adopt F12, dsh `packages/goal/store`) requires: the goal state machine stored as event sourcing, updates with optimistic concurrency control, conflicts rejected.

The realistic landing spot here is not GoalTree (deleted, see orch-dynamic) but the **TaskService task-record state machine**.

## Decision

**The record KV is a projection; the journal is the single source of truth. Internal transitions stay last-writer-wins; external updates must CAS.**

1. **Event sourcing**: the `tasks-journal` event stream (`TaskJournalEvent`: Seq/TS/Task/From/To/Revision/Note/Conflict) is the single source of truth; the record KV is its projection. Seq is monotonic and Revision is the post-event record revision — a continuous chain replays the state machine's evolution (`ReadJournal`). **Rejected CAS conflicts are also journaled** (`Conflict: true`) — a rejected update is precisely where audit value lives.
2. **`TransitionCAS(id, expectRevision, mutate)`**: carries the previously-read Revision as an expectation check; a mismatch returns `ErrStateConflict`. `mutate` receives an unlocked copy of the record and declares the target state and field changes on it; the service maintains the revision — mutate need not and must not increment it. Returning `(nil, nil)` means "no write this time".
3. **Two-track concurrency discipline** (both modes kept deliberately): internal transitions (`transition`) remain last-writer-wins — they are the state machine's own progression (running/failed/…), and forcing CAS there would only add meaningless conflicts; external multi-agent updates **must** go through `TransitionCAS` / `Refine`, with unversioned read-modify-write no longer allowed.
4. **No cross-process idempotence promised**: the statestore FileStore lock is per-instance; two processes pointing at the same stateDir and submitting concurrently may each create a record. CAS solves **within-instance** multi-agent concurrency; cross-process idempotence is carried by the action queue's os.Rename claim. The boundary is documented in the taskservice.go package comment.

## Verification

- `pkg/agent/taskservice_cas_test.go` (-race green): mismatched revision rejected (ErrStateConflict), matching revision migrates and advances Revision, rejected conflict leaves a Conflict event in the journal, Refine goes through CAS with journaling.
