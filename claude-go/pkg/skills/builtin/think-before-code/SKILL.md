# Think Before Code（先思考，后编码）

> 受 Karpathy 原则启发：在编写任何代码之前，必须先完成思考阶段。

## 强制思考阶段

在生成**任何**代码或修复之前，你必须在 `<think>...</think>` 标签内完成以下思考：

1. **目标重述**：用一句话重述本次任务的目标。
2. **约束清单**：列出 Contract Context 中你计划使用的所有接口/类型。
3. **变更范围**：估算 (a) 需要修改的文件数，(b) 新增行数，(c) 删除行数。
4. **假设声明**：声明你对代码库做出的任何假设（例如，"假设接口 X 已存在"）。
5. **方案对比**：如果存在多种实现方式，说明你选择当前方案的理由。
6. **停止条件**：在什么情况下你会停止并寻求用户帮助，而不是继续推进？

## 根因分析（修复场景）

如果是修复编译错误，思考阶段还必须回答：

1. **根因**：真正的根本原因是什么（不是表面症状）？
2. **最小修复**：修复此错误的最小变更是什么？
3. **副作用**：这个修复会破坏其他东西吗？你如何确定？
4. **何时停止**：如果你无法用两句话解释根因，STOP 并说明情况。

## Think Phase 检查清单

- [ ] `<think>` 标签已输出
- [ ] 所有 6 个思考项已回答（生成场景）或所有 4 个根因项已回答（修复场景）
- [ ] 变更范围已声明（文件 + 行数估算）
- [ ] 停止条件已明确

## 禁止事项

- **禁止** 跳过思考阶段直接生成代码
- **禁止** 在思考不完整时开始编码
- **禁止** 用模糊表述敷衍思考项（如 "我会看看"）
