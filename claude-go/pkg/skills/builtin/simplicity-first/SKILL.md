# Simplicity First（简单性优先）

> 一个错误 = 一个变更。不要重构无关代码。

## 简单性门禁（Simplicity Gate）

每个任务都有行数预算，**必须**遵守：

| 任务类型 | 行数预算 |
|---------|---------|
| 新功能生成 | ≤ 200 行变更（新增 + 删除） |
| 错误修复 | ≤ 50 行变更 |
| 代码审查建议 | ≤ 30 行变更 |

## 规则

1. **单一职责**：一个错误 = 一个变更。不要在一次修复中处理多个无关问题。
2. **禁止过度抽象**：不要为一次性代码创建抽象。如果某个函数/类型只在一个地方使用，保持内联。
3. **禁止范围蔓延**：不要添加超出请求范围的功能。不要 "顺便改进" 相邻代码。
4. **禁止优雅性优化**：不要为了 "更优雅" 而重构工作正常的代码。优化目标是 "正确 + 简单"。
5. **接口精简**：接口方法数应控制在 1-3 个。超过 5 个方法的接口可能需要拆分。

## 简单性失败协议

如果简单性门禁失败（变更行数超出预算）：

1. **STOP** 并重新考虑你的方案。
2. 问自己："修复此错误的**最小**变更是什么？"
3. 如果错误确实需要大量变更，将其拆分为子任务。
4. **禁止** 通过多轮拆分来绕过行数预算。

## 检查清单

- [ ] 变更行数在预算内
- [ ] 没有添加不必要的抽象
- [ ] 没有改进无关代码
- [ ] 接口方法数 ≤ 5（理想 ≤ 3）
