# Surgical Changes（外科手术式变更）

> 只修改你在思考阶段声明的文件。不要改变相邻代码。

## 变更范围规则

1. **声明即边界**：只修改在 Think Phase 中声明的文件。未声明的文件一律不动。
2. **行级精确**：每一行变更都必须能直接追溯到任务目标。无关行不得触碰。
3. **保留相邻代码**：
   - 不要修改修复区域外的注释
   - 不要重命名修复区域外的变量
   - 不要调整修复区域外的格式
4. **风格一致**：新增代码必须匹配现有代码的命名风格、错误处理模式和注释习惯。

## 什么是附带损伤（Collateral Damage）

以下行为属于附带损伤，**严格禁止**：

- 修改未声明的文件
- 重命名与错误无关的变量/函数
- 添加 "更好" 的错误处理到未涉及代码
- 调整 import 排序（除非 import 本身与修复相关）
- 修改测试期望值来让测试通过

## 外科手术式失败协议

如果外科手术门禁失败（检测到附带损伤）：

1. **STOP**。回滚对未声明文件的变更。
2. 回顾你在 Think Phase 中的变更范围声明。
3. 只重新应用与错误直接相关的变更。
4. **禁止** 在修复错误时 "改进" 相邻代码。

## 编辑片段规则

使用 `//...existing code...` 标记未变更的边界：

```json
[{
  "file": "relative/path/to/file.go",
  "start_marker": "//...existing code...",
  "end_marker": "//...existing code...",
  "replacement": "// new code"
}]
```

- 保持替换最小（通常 3-20 行）
- 绝不删除与修复无直接关系的行
- 保留注释和格式

## 检查清单

- [ ] 只修改了声明范围内的文件
- [ ] 没有重命名无关变量
- [ ] 没有调整无关格式
- [ ] 每一行变更都能追溯到任务目标
